# 에이전트 작업과 인수인계

이 문서는 현재 작업의 운영 절차다. 제품 불변식은 [AGENTS.md](../../AGENTS.md), 전체 QA 계약은 [품질 규칙](../quality/rules.md), 검사 선택은 [QA 탐색](../quality/navigation.md)을 따른다. 역할은 책임을 나누는 단위이며 작업마다 에이전트 8개를 생성할 필요는 없다.

## 시작과 파일 소유권

1. 박자는 사용자 요청, 기존 변경, 활성 계획과 worktree를 읽고 범위를 정한다. 구현 전에 활성 계획을 만들고 전용 branch/worktree를 사용한다.
2. 구성은 계획의 Owner와 Implementation Plan에 각 담당자의 결과물, 쓰기 가능한 파일·디렉터리, 선행 조건을 기록한다. 채팅에만 남은 범위 결정은 Decision Log에 옮긴다.
3. 동시에 진행 가능한 작업만 위임한다. 같은 worktree에서는 파일마다 쓰기 담당자를 한 명 정한다. 공용 `package.json`, `run_qa.py`, 계획·완료 문서는 수정 전에 담당자와 조율한다. 다른 에이전트의 변경을 되돌리거나 별도 브랜치라고 가정하지 않는다.
4. 에이전트는 맡은 범위의 구현과 관련 QA 결과를 반환한다. 병합·커밋·앱 교체·Downloads 전달은 박자가 조율한다. 실제 앱을 다루는 QA는 한 담당자가 순차 실행하여 창 포커스와 공용 산출물 충돌을 막는다.

## 역할별 완료 조건

| 역할 | 반환할 결과 | 다음 담당자 |
|---|---|---|
| 박자 / project_lead | 사용자 범위, 승인된 외부 작업, 작업 분할과 최종 완료 근거 | 구성·구현 담당자 |
| 구성 / plan_keeper | 현재 상태, 결정 이유, 담당 범위, QA·리뷰 링크 | 박자 |
| 지도 / repo_cartographer | 현재 진입 문서, 코드·검사 위치, 끊어진 경로 수정 | 제작·구성 |
| 제작 / harness_builder | 재현 가능한 개선, 변경 경로, 관련 검사와 실패 근거 | 검증 |
| 검증 / quality_runner | 실행 환경, 명령·종료 코드, 실패·재실행 기록, 산출물 경로 | 심사 |
| 심사 / review_judge | QA 이후 결함·근거·심각도, 미해결 위험과 후속 제안 | 박자·구성 |
| 수호 / privacy_guard | 구체적인 입력·저장·권한·외부 전송 경계와 재현 가능한 결함 | 구현 담당자·검증 |
| 정리 / doc_gardener | 완료 계획·리뷰의 연결, 현재 안내와 역사 기록의 구분 | 구성 |

역할명 자체는 코드 쓰기 권한이나 외부 서비스 작업 승인이 아니다. 실제 소유 범위와 권한은 현재 사용자 요청 및 활성 계획에 따른다. 제품 코드 담당 역할을 별도로 고정하지 않으며 박자가 파일 소유자를 지정한다.

## 구현에서 QA로

인수인계에는 다음을 포함한다. 증거는 계획 Progress Log에 요약하고 큰 로그·오디오·스크린샷은 ignored `build/desktop/`에 보관한다.

```text
계획 / 담당자 / 인수인계 대상:
변경 파일과 동작 / 재현한 결함:
실행한 명령 / 종료 코드 / 실행 시각:
branch / HEAD / worktree / 미커밋 변경 유무:
산출물 경로 / 검증 범위 / 아직 수행하지 않은 검사:
남은 위험 / 다음 단계:
```

HEAD만으로 미커밋 구현을 식별할 수 없다. 미커밋 상태라면 그 사실을 기록하고 설치본·배포 파일을 주장할 때 실제 파일 해시와 빌드 근거를 연결한다. 계획이나 공개 문서에 사용자 홈의 실경로, 개인 제목, 비밀 값을 복사하지 않는다.

## QA에서 리뷰로

`npm run release:check`와 작업 범위에 필요한 추가 QA가 끝난 뒤 심사가 리뷰를 시작한다. 구현 담당자의 자체 검토는 독립 완료 리뷰를 대신하지 않는다. 에이전트 수가 제한되면 구현이 끝난 담당자를 대기시키고 리뷰 역할을 별도 실행한다.

실패를 고치면 영향을 받은 검사를 다시 실행하고, 최종 변경 이후 전체 게이트의 유효성을 확인한다. 실패 또는 미실행 항목이 남으면 통과로 기록하지 않는다. 환경 제약과 외부 배포 차단은 앱 기능 실패와 구분하여 실제 상태를 기록한다. 리뷰에서 수정이 생기면 QA와 리뷰 인수인계를 다시 거친다.

구성이 완료 계획을 `docs/exec_plans/completed/`로 옮기고 `docs/reviews/`에 QA·검토·잔여 위험을 요약한다. 박자는 저장소의 병합·push·정리 절차를 수행한다. main checkout에서 완료 worktree가 깨끗한지 확인해 제거한 다음 `git branch -d`로 병합한 branch를 삭제한다. worktree에서 checkout 중인 branch는 Git이 삭제를 거부하므로 순서를 바꾸지 않는다. 정리는 통합한 작업의 branch/worktree만 대상으로 한다.
